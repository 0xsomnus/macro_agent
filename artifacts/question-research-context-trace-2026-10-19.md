# Retained investigation context proof

The [exact fictional trace](question-research-context-trace-2026-10-19.json) runs through Django's session/CSRF API and an isolated PostgreSQL database. It uses recorded model and discovery responses, without existing trader records, real model calls or live financial research.

1. Save the exact rough question. One recorded planning call names a supply question and a separate replacement-supply counter-question.
2. The first recorded search returns five candidates. Retain four and explicitly exclude the fifth. Interrupt after durable capture, before its availability witness and discovery-result record.
3. Close connections and read saved state. Explicit continuation adopts the committed capture without repeating that search, then runs the previously unadmitted counter-search once. It returns zero candidates.
4. Freeze a v2 packet with both exact planned questions, every completed query outcome, original record digests, pinned source contracts and complete selected revision membership. The empty counter-search remains visible.
5. One recorded compilation receives that same packet. Planning and acquisition context are untrusted workflow data, separate from trader intent and source quotations. Empty search results cannot establish a false mechanism or an adequately researched counter-case.
6. Correct a selected source and remove model credentials. Saved reads, original-command retry and explicit continuation preserve the original plan, packet and model document while reporting stale disposition. They make no replacement inference or search.

Both query sources remain dependencies, including the empty search. Separate PostgreSQL tests withdraw its permission and verify stale inspection and blocked new approval. Direct database tests reject foreign runs, omitted queries and missing/null packet or model-profile versions. Legacy interrupted packets retain their original hashes and prompt identities.

The proof makes two recorded model completions and two recorded searches. It creates no watch, approval, paper position, current assessment or notification intent. Real model/network calls and real model spend are zero; recorded provider charges remain unknown. The disposable database is dropped afterward.

Reproduce from the configured repository terminal:

```sh
MACRO_ALLOW_SYNTHETIC_SETUP=1 MACRO_ENABLE_MONITORING_PROOF=1 \
DJANGO_SETTINGS_MODULE=macro_agent.web.local_settings \
.venv/bin/python tools/question_research_demo.py --output .local/question-research-context-trace.json
```

This proves retained context, authority and recovery mechanics. It does not prove semantic support, causal attribution, adequate counter-research, live source availability or model usefulness. The interruption is an application exception plus connection restart, not an operating-system crash. See the separate [live source recheck](../research/research-source-recheck-2026-10-19.md).
