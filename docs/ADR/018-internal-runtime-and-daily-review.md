# ADR 018: Internal runtime and daily evidence review

Status: Accepted by user review on 2026-10-09. This selects an internal test direction, not production infrastructure or an unattended activation policy.

**Decision:** Begin with deterministic daily evidence reviews and separate Django capture and analytical processes, backed by durable PostgreSQL scheduling and leases. Defer production queue selection until operating evidence justifies it. Capture must continue when inference is unavailable or slow.

**Why:** The next test targets workflow durability with narrow permitted headline inputs. A retained-evidence review exposes missing work and continuity before adding another paid synthesis call. Process separation prevents model latency from blocking polling while keeping scheduling and recovery inspectable in the established database.

**Daily content:** Include attributed reports and retained analyses available during the previous reporting interval, with original contexts, outcomes, labels, unresolved work, coverage gaps and known/unknown costs. A late analysis of an older report belongs to the interval in which the analysis becomes conservatively available. Its source must also be eligible by the cutoff. No new model call is required for assembly; this is not yet a synthesized macro brief.

**Time:** Use explicit `(previous cutoff, current cutoff]` boundaries and separate conservative postcommit availability witnesses for reports and analyses. A witness is an upper bound, not an exact commit time; publication, receipt or analysis finish cannot replace it. Missing witnesses defer eligibility without invented backdating. Preserve original decisions separately from current disposition observed at actual preparation. Preparation may follow the reporting cutoff and does not reconstruct cutoff currentness.

**Authority and recovery:** Preserve exact approved text/interpretation, complete attached exposure and source-contract versions. Facts, attributed source statements and agent interpretation remain distinct. Store stable work and command identities before model admission. Unadmitted work may recover through leases; an admitted uncertain call requires outcome inspection, not an automatic paid retry. Lease expiry, restart or a missed slot does not prove remote cancellation or zero billing. Daily slot identity must prevent duplicate artifacts across retries and schedule changes.

**Publication:** Daily publication admission and correction-aware dependencies still need implementation; the pure assembly candidate has no publication authority. Source corrections, permission changes, approval and exposure writers must share the [ADR 015](015-auditable-publication.md) ordering protocol. Correction-first blocks stale publication; publication-first preserves the original decision before atomically invalidating current output and pending notices. Late same-context work cannot replace a newer current revision. No external delivery is selected here.

**Research scope:** The selected starting question concerns assets affected by AI buildout and whether positioning over a few weeks to months is late. The [research pack](../../research/ai-infrastructure/2026-10-09/PILOT_SCOPE.md) checks public Exness `XCUUSD` and named AMD/NVDA perp listings. Account eligibility, application mapping, actual exposure, basis/financing and supported equity valuation remain unresolved. These gaps can stay explicit in manual paper workflow tests. No trading thesis, position or source manifest is approved by this ADR.

**Initial implementation evidence, 2026-10-09:** The pure [daily-review domain module](../../src/macro_agent/domain/daily_review.py) and 22 recorded-input tests establish bounded deterministic assembly and inspection rules. They do not establish database scheduling, availability-witness collection, a context chain, publication integration, continuous operation or live analytical quality. See [CONTEXT_CONTINUITY.md](../CONTEXT_CONTINUITY.md) and the [weekly test](../WEEKLY_WORKFLOW_TEST.md).

**Still open before activation:** Cadence and detection target; daily time/timezone; record, context and fanout bounds; allowances and the open dollar ceiling; operator resolution of ambiguous calls; reviewed thesis/source manifest; and race/restart evidence through independent PostgreSQL connections. The accepted direction does not supply defaults for these policies.

**Missed-slot clarification, accepted 2026-10-10:** Create each missed daily review once and label it late. Preserve intended cutoff and actual preparation time. Process daily dates oldest first; a blocked older daily slot bars newer assembly. Coalesced periodic polls record missed intervals without claiming recovered feed coverage.

**Internal implementation, 2026-10-10:** Immutable evidence sets, private predecessor contexts, exact exposure references, versioned source permission, PostgreSQL scheduling/leases and separate capture/analysis operator commands now implement this direction. A conservative marker precedes news-model admission; recovery after that marker only inspects the saved command. Capture and deterministic daily assembly remain independent of paid-analysis caps. See [the runner guide](../CONTINUOUS_RUNNER.md) and [implementation evidence](../IMPLEMENTATION.md). No current daily publication pointer, external notification, cumulative LLM macro assessment or unattended production activation is added.
